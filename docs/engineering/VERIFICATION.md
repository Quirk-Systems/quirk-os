## Practical limitations

The SQL runner uses stubbed `auth.uid()` and Supabase roles. Its 14 groups verify local tenant isolation, visibility, stale source binding, contradictions, supersession, bounded traversal and append-only behavior, including attempted truncation. It does not verify the real identity provider, PostgREST, live grants, concurrency or a deployed database.

SQLite triggers protect ordinary application writes. A filesystem/database owner can change storage, so `immutable` is not asserted. Append-only audit data still needs a production retention/redaction policy. Loop callbacks are trusted host code with cooperative deadlines; external adapters must enforce their own timeouts. The pilot's filesystem source pointer is intended for a single operator.

The runtime still emits a local canceled-request diagnostic reproduced on unchanged source. Its authority-change pause is a terminal application receipt while Workflow status is complete; it is not implemented Workflow suspension/resume. Production persistence, atomic arbitration and exactly-once external effects remain unproved.

Projection validation minimizes structured exports and rejects known sensitive shapes. It is not a general secret scanner or proof that arbitrary text is public. A trusted collector must select public/synthetic inputs and verify human evidence references before using those APIs. Published regression fixtures cannot supply an untouched held-out result. Reconstruction benefit, manual-rescue reduction and accepted human preference remain unmeasured.
