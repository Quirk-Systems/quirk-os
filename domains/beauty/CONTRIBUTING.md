# Contributing

1. Name the change class: canon, candidate semantics, runtime, projection, design, model adapter, evaluation, sales, or proof.
2. Add or update a failing test before changing behavior.
3. Preserve actor and purpose lineage.
4. Keep recommendation separate from action and outcome separate from graph mutation.
5. Do not mark candidate material canonical.
6. Run `npm run ci`.
7. Attach commands, outputs, paths, digests, and unresolved risks.
8. Request `APPROVE / REVISE / HOLD / SUPERSEDE` rather than assuming acceptance.

A generated artifact, passing unit test, attractive screen, or model score cannot self-admit.
