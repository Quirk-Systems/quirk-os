# Taste Engine Proof

## Claim under test

The v0.1 pack does not need to prove that Quirk Beauty is a platform or that its recommendation algorithm is generally superior.

It must prove one narrower thing:

> One explicit beauty choice can travel through preference evidence, recommendation, real-world outcome, and a human-confirmed graph update without losing lineage or manufacturing authority.

## Current verdict

**BLOCKED — real-world run not yet performed.**

The included synthetic fixture verifies code paths, state transitions, receipts, and denials. It is deliberately rejected by the real-proof verifier.

## Evidence bundle

A passing `proof/evidence/real-proof.json` must contain:

- the original explicit choice;
- all derived preference evidence;
- the recommendation and evidence IDs used;
- an explicit outcome recorded after real-world use;
- the graph-update proposal;
- the human decision;
- the final graph-update receipt;
- SHA-256 digests for every artifact;
- participant consent and operator attestation.

## Why one run is enough—and not enough

One run is enough to prove the **constitutional and technical path exists**.

It is not enough to prove recommendation lift, commercial demand, population-level accuracy, or a stable taste model. Those require repeated trials and separate evaluation gates.
