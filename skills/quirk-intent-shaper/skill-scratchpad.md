# Quirk Intent Shaper — `skill-scratchpad.md`

**Status:** Candidate exploration surface  
**Rule:** Scratchpad ideas are not Canon, runtime authority, or product promises. Promotion requires typed contracts, evidence, evaluation, ownership, and human admission.

## Compression bomb

> Compile what the person is trying to change, who they need to be for this task, how Quirk should sound and look, what the destination platform changes, and which interaction form makes the work easier—then learn only through inspectable feedback.

## Working definition

**Quirk Intent Shaper** is a candidate Skill that turns heterogeneous personalization evidence into a reversible execution plan for one task.

It does not generate a personality.

It compiles a **purpose-bound relationship contract**.

## Eleven signature Moves

### 01 · Intent Distillation

Separate:

```text
what was said
what is wanted
what must change
what counts as done
what must not be changed
```

### 02 · Purpose Partitioning

A preference is never globally true merely because it was once useful.

Examples:

- BryMinn performance preferences do not control a legal memo.
- GitHub terseness does not dictate an anniversary letter.
- “Challenge me” does not authorize adversarial behavior during urgent emotional support.
- A dashboard preference does not justify building one for a two-line decision.

### 03 · Persona Hand Selection

Use:

```yaml
primary:
  ref: persona.brayn
  role: system_architecture
  weight: 0.65

supporting:
  - ref: persona.bryan
    role: reality_grounding
    weight: 0.25
  - ref: persona.brayk
    role: overlooked_seams
    weight: 0.10
```

Never let personas impersonate Bryan or acquire authority.

### 04 · Voice Constitution Compilation

Compile from:

- positive examples;
- rejected examples;
- lexical rules;
- sentence density;
- humor tolerance;
- profanity tolerance;
- evidence requirements;
- banned clichés;
- desired emotional pressure;
- format and destination.

A voice contract should say both **what to do** and **what not to fake**.

### 05 · Tone as Context, Not Identity

Tone is a temporary operating condition:

```text
warm ↔ severe
plain ↔ theatrical
calm ↔ urgent
formal ↔ conversational
restrained ↔ feral
supportive ↔ adversarial
```

Weights are selected by task, not merely preference.

### 06 · Aesthetic as Decision Support

Aesthetic decisions should affect:

- hierarchy;
- density;
- contrast;
- pacing;
- spatial grouping;
- texture;
- motion;
- image/reference use;
- information reveal;
- memorability.

Aesthetic must not hide status, evidence, cost, uncertainty, or authority.

### 07 · Platform Affect Resolution

A platform creates pressure:

| Platform | Affect | Preferred affordances | Prohibited shortcut |
| --- | --- | --- | --- |
| GitHub | versioned, reviewable, diff-driven | patch, tests, issue, receipt | prose-only “done” |
| Google Drive | authored, shareable, review-oriented | document, comments, evidence pack | treating Doc as executable Canon |
| Airtable | operational, row/state-oriented | fields, views, batch review | free-text truth |
| Notion | navigational, explanatory | linked pages, progressive disclosure | wiki page as runtime authority |
| Vercel | delivery and preview | commit-bound preview, logs, rollback | successful build as admission |
| Cloudflare | edge/security pressure | explicit provider boundary | hidden duplicate runtime |
| Email | relational and temporal | finished message, subject, reply context | dumping analysis into the sendable body |
| Chat | interruptible and iterative | concise answer, one useful next move | ceremony |

| Mobile | glance, interruption, touch | cards, large actions, resumability | desktop dashboard shrink-ray |
| Music | breath, performance, narrative energy | section map, vocal mechanics | generic genre labels |

### 09 · Candidate Generation

Generate a small Pareto set rather than one averaged compromise:

- **Default:** best overall intent fit.
- **Sharp edge:** more original or assertive.
- **Conservative:** higher certainty, lower interpretation.
- **Wildcard:** only when the task benefits from genuine divergence.

### 10 · Alignment Tribunal

Score independently:

```text
intent_fit
preference_fit
voice_fidelity
platform_fit
task_affordance_fit
evidence_quality
authority_compliance
accessibility
novelty
independent_reusability
strange_intact
```

Use pointwise evaluation before pairwise ranking to reduce superficial comparison bias.

### 11 · Feedback Without Invisible Destiny

Classify feedback:

```text
ACCEPTED
EDITED
REJECTED
IGNORED
CONTEXT_CHANGED
PREFERENCE_CHANGED
TASK_MISMATCH
PLATFORM_MISMATCH
```

Then record:

- exact candidate;
- exact edit or reaction;
- purpose;
- platform;
- confidence delta;
- whether the signal is one-off or repeated;
- a proposed preference update;
- human admission status.

## Eleven AI techniques worth integrating

### 1. Purpose-scoped preference retrieval

Retrieve only preference evidence relevant to the current purpose, rather than injecting a giant user profile into every prompt.

### 2. Natural-language preference distillation

Compress noisy interaction history into short, inspectable preference summaries that can be edited by the user.

### 3. Pairwise preference elicitation

Use ranked pairs to learn subtle taste, but combine with pointwise evaluation so verbosity, confidence, or polish do not win by default.

### 4. Hierarchical Bayesian preference models

Represent:

```text
global tendency
+ domain tendency
+ platform tendency
+ current-task override
```

This permits learning from sparse feedback without pretending every preference is universal.

### 5. Contextual preference bandits

For reversible, low-stakes choices, explore bounded alternatives and learn from selections. Never use this for protected actions, sensitive inference, or hidden behavior changes.

### 6. Contrastive style and aesthetic representations

Learn what distinguishes “this feels like Quirk” from near-miss examples through positive/negative pairs, not generic style adjectives.

### 7. Activation steering or soft preference controls

Use lightweight inference-time controls for temporary dimensions such as concision, warmth, directness, or novelty when supported by the model and exposed to the user.

### 8. Multi-objective reranking

Do not collapse every criterion into one opaque score. Preserve a Pareto frontier across intent, evidence, voice, cost, latency, risk, novelty, and effort.

### 9. Counterfactual personalization testing

Run the same intent through:

- no personalization;
- purpose-only personalization;
- full preference plan;
- wrong-persona adversary;
- wrong-platform adversary.

The personalized result must improve the task without violating invariants.

### 10. Generative UI with an affordance grammar

Generate an interface only when interaction improves the work. UI plans must be schema-constrained, accessible, reversible, and rendered from admitted components.

### 11. Personalization drift detection

Detect when:

- feedback reverses an old preference;
- a preference stops predicting choices;
- a platform changes;
- a persona is over-selected;
- the system becomes stylistically repetitive;
- remembered instructions no longer fit current behavior.

Drift emits an `AdaptationProposal`; it never silently rewrites the user.

## Additional techniques in the boneyard / lab

- per-purpose LoRA or adapter candidates for high-volume stable domains;
- model routing by user/task preference graph;
- uncertainty-aware active elicitation;
- critique-conditioned regeneration;
- edit-distance and revision-pattern learning;
- multimodal taste retrieval from images, audio, layout, and performance clips;
- synthetic user simulation for negative testing;
- accessibility adaptation with explicit user controls;
- causality-aware signal weighting so dwell time does not masquerade as preference;
- temporal decay and reaffirmation prompts;
- local/on-device preference encoding for sensitive partitions.

6. Test explicit preference overrides against inferred history.
7. Test stale preference detection and supersession.
